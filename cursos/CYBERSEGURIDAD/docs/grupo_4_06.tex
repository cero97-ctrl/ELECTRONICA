\section{\iconotexto{user-shield}{Tu rol en la práctica}}

Parte de su propia captura cruda y aplica el control equivalente: configuración, parche o regla de red. Repite el ataque para demostrar que falla y documenta el antes y el después.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Leer su propia evidencia cruda y elegir el control que corta el ataque en el punto más barato.
  \item Aplicar el control y repetir el ataque para demostrar que ya no funciona.
  \item Documentar el antes y el después con los mismos comandos y la diferencia medida.
\end{itemize}

\section{\iconotexto{list-ol}{Ejemplo paso a paso}}

El rol Azul escribe el auditor que decide, aplica los cambios y demuestra con la misma herramienta que el estado cambio. El entregable es la comparacion, no la configuracion sola.

\subsection{Escribir el auditor con veredicto por control}

El auditor emite una linea por control con estado y veredicto. Un control no medible devuelve "no\_verificado", no un aprobado por defecto.

\begin{lstlisting}[style=estiloCodigo]
mkdir -p semana_06/evidencia
cat > semana_06/auditor.py <<'PY'
import subprocess

def sshd(clave):
    salida = subprocess.run(['sshd', '-T'], capture_output=True, text=True)
    for linea in salida.stdout.splitlines():
        if linea.startswith(clave):
            return linea.split()[1]
    return 'no_verificado'

controles = {
    'permitrootlogin': sshd('permitrootlogin'),
    'passwordauthentication': sshd('passwordauthentication'),
}
for nombre, valor in controles.items():
    if valor == 'no_verificado':
        veredicto = 'no_verificado'
    else:
        veredicto = 'ok' if valor == 'no' else 'fallo'
    print(nombre, valor, veredicto)
PY
python3 semana_06/auditor.py | tee semana_06/evidencia/veredictos_antes.txt
\end{lstlisting}

\subsection{Aplicar el hardening por lotes con vuelta atras}

Se copia la configuracion antes de tocarla y se recarga solo lo necesario. Si un servicio no vuelve a arrancar, se restaura la copia.

\begin{lstlisting}[style=estiloCodigo]
sudo cp /etc/ssh/sshd_config semana_06/evidencia/sshd_config.orig
sudo sed -i -E 's/^#?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl reload ssh 2>/dev/null || sudo kill -HUP 1
sudo ufw default deny incoming
sudo ufw allow 2222/tcp
sudo ufw --force enable
python3 semana_06/auditor.py | tee semana_06/evidencia/veredictos_despues.txt
\end{lstlisting}

\subsection{Comparar y justificar excepciones}

Se comparan los veredictos y se justifica cada control que sigue en fallo. La excepcion se documenta con su motivo y su fecha de revision.

\subsection{Verificar que el sistema sigue operativo}

Un hardening que deja el sistema inaccesible no es un hardening. Se comprueba el acceso permitido y el servicio que el grupo necesita.

\begin{lstlisting}[style=estiloCodigo]
ss -tulpn | tee semana_06/evidencia/puertos_final.txt
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/ \
  | tee semana_06/evidencia/http_final.txt
\end{lstlisting}
