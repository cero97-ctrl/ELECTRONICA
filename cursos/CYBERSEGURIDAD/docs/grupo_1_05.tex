\needspace{5\baselineskip}
\section{\iconotexto{user-shield}{Tu rol en la práctica}}

Parte de su propia captura cruda y aplica el control equivalente: configuración, parche o regla de red. Repite el ataque para demostrar que falla y documenta el antes y el después.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Leer su propia evidencia cruda y elegir el control que corta el ataque en el punto más barato.
  \item Aplicar el control y repetir el ataque para demostrar que ya no funciona.
  \item Documentar el antes y el después con los mismos comandos y la diferencia medida.
\end{itemize}

\section{\iconotexto{flag}{Qué aporta este rol al entregable}}

\needspace{5\baselineskip}
\section{\iconotexto{list-ol}{Ejemplo paso a paso}}

El rol Azul reproduce la falla y despues aplica el control que la corta, sin cambiar el payload. Si el resultado cambia porque se cambio la peticion, no se demostro nada.

\subsection{Iniciar sesion y fijar el nivel de DVWA}

Todo se ejecuta con la sesion del laboratorio y el nivel bajo, que es el que se quiere demostrar vulnerable. El token CSRF se extrae de la pagina, no se supone.

\begin{lstlisting}[style=estiloCodigo]
mkdir -p semana_05/evidencia
curl -s -c semana_05/evidencia/cookies.txt \
  http://127.0.0.1:8081/login.php > semana_05/evidencia/login.html
TOKEN=$(grep -o "name='user_token' value='[^']*'" \
  semana_05/evidencia/login.html | head -1 | cut -d"'" -f4)
curl -s -b semana_05/evidencia/cookies.txt -c semana_05/evidencia/cookies.txt \
  -d "username=admin&password=password&Login=Login&user_token=$TOKEN" \
  http://127.0.0.1:8081/login.php -o /dev/null
curl -s -b semana_05/evidencia/cookies.txt \
  -d "security=low&seclev_submit=Submit" \
  http://127.0.0.1:8081/security.php -o /dev/null
\end{lstlisting}

\subsection{Capturar la evidencia de los tres hallazgos}

Cada peticion se guarda con su respuesta completa. El reflejo del XSS, la fila extra de la inyeccion y el contenido del archivo leido son la prueba, y se guardan tal cual.

\begin{lstlisting}[style=estiloCodigo]
curl -s -b semana_05/evidencia/cookies.txt \
  'http://127.0.0.1:8081/vulnerabilities/xss_r/?name=%3Cscript%3Ealert(1)%3C/script%3E' \
  > semana_05/evidencia/xss_antes.html
curl -s -b semana_05/evidencia/cookies.txt \
  'http://127.0.0.1:8081/vulnerabilities/sqli/?id=1%27+OR+%271%27%3D%271&Submit=Submit' \
  > semana_05/evidencia/sqli_antes.html
curl -s -b semana_05/evidencia/cookies.txt \
  'http://127.0.0.1:8081/vulnerabilities/fi/?page=../../../../etc/passwd' \
  > semana_05/evidencia/lfi_antes.txt
sha256sum semana_05/evidencia/*_antes.* > semana_05/evidencia/antes.sha256
\end{lstlisting}

\subsection{Aplicar el control que elimina la causa}

El control se aplica donde esta la causa: parametrizacion y codificacion en la aplicacion, o nivel alto de DVWA cuando el codigo no se puede editar. Se elige uno y se documenta el motivo.

\begin{lstlisting}[style=estiloCodigo]
curl -s -b semana_05/evidencia/cookies.txt \
  -d "security=high&seclev_submit=Submit" \
  http://127.0.0.1:8081/security.php -o /dev/null
printf 'nivel alto aplicado; se documenta que el control es de la aplicacion\n' \
  > semana_05/evidencia/control.txt
\end{lstlisting}

\subsection{Repetir exactamente el mismo payload}

Las mismas URL, el mismo orden y la misma sesion. El resultado esperado es que el reflejo se codifique, la inyeccion no devuelva filas extra y el archivo no se lea.

\begin{lstlisting}[style=estiloCodigo]
curl -s -b semana_05/evidencia/cookies.txt \
  'http://127.0.0.1:8081/vulnerabilities/xss_r/?name=%3Cscript%3Ealert(1)%3C/script%3E' \
  > semana_05/evidencia/xss_despues.html
grep -c '&lt;script&gt;' semana_05/evidencia/xss_despues.html
curl -s -b semana_05/evidencia/cookies.txt \
  'http://127.0.0.1:8081/vulnerabilities/fi/?page=../../../../etc/passwd' \
  | wc -c > semana_05/evidencia/lfi_despues.txt
\end{lstlisting}

\section{\iconotexto{box-open}{Qué guardar en el repositorio}}

El informe muestra, por hallazgo, la peticion, la respuesta antes, el control aplicado y la respuesta despues con el mismo payload, mas el hash de la evidencia.

\begin{lstlisting}[style=estiloCodigo]
semana_05/
|-- informe.md
|-- evidencia/
|   |-- cookies.txt
|   |-- xss_antes.html
|   |-- xss_despues.html
|   |-- sqli_antes.html
|   |-- sqli_despues.html
|   |-- lfi_antes.txt

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item El payload de antes y el de despues son identicos byte a byte.
  \item El control se aplico en la causa, no en el enunciado del informe.
  \item La sesion y el nivel de seguridad estan documentados.
  \item La evidencia esta anonimizada antes de versionarse.
\end{itemize}
