\needspace{5\baselineskip}
\section{\iconotexto{user-shield}{Tu rol en la práctica}}

Parte de su propia captura cruda y aplica el control equivalente: configuración, parche o regla de red. Repite el ataque para demostrar que falla y documenta el antes y el después.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Leer su propia evidencia cruda y elegir el control que corta el ataque en el punto más barato.
  \item Aplicar el control y repetir el ataque para demostrar que ya no funciona.
  \item Documentar el antes y el después con los mismos comandos y la diferencia medida.
\end{itemize}

\section{\iconotexto{flag}{Qué aporta este rol al entregable}}

La mitigación aplicada, el comando de verificación y la comparación de resultados.

\needspace{5\baselineskip}
\section{\iconotexto{list-ol}{Ejemplo paso a paso}}

El rol Azul aplica el playbook al incidente de la semana 8: contiene, erradica y comprueba que el servicio vuelve sin el mecanismo de persistencia.

\subsection{Contener sin destruir evidencia}

Se aísla el servicio y se preserva la evidencia antes de borrar nada. Contener no es limpiar: es evitar la propagacion sin perder el rastro.

\begin{lstlisting}[style=estiloCodigo]
mkdir -p semana_09/evidencia
docker stop objetivo-linux | tee semana_09/evidencia/contencion.txt
docker inspect objetivo-linux > semana_09/evidencia/contenedor_antes.json
\end{lstlisting}

\subsection{Erradicar la persistencia identificada}

Se eliminan solo los mecanismos confirmados en la semana 8. Cada eliminacion se registra con el comando y el motivo.

\begin{lstlisting}[style=estiloCodigo]
docker start objetivo-linux
docker exec objetivo-linux sh -c 'crontab -l 2>/dev/null || true' \
  > semana_09/evidencia/cron_antes.txt
docker exec objetivo-linux sh -c 'rm -f /etc/cron.d/sospechoso' \
  | tee semana_09/evidencia/erradicacion.txt
\end{lstlisting}

\subsection{Verificar que la persistencia no volvio}

Se repite la busqueda del mecanismo eliminado. Si el archivo reaparece, hay otra persistencia que alimenta el primero y la erradicacion no termino.

\begin{lstlisting}[style=estiloCodigo]
docker exec objetivo-linux sh -c 'ls /etc/cron.d/ 2>/dev/null' \
  | tee semana_09/evidencia/cron_despues.txt
docker exec objetivo-linux sh -c 'ps -eo pid,cmd' \
  | tee semana_09/evidencia/procesos_despues.txt
\end{lstlisting}

\subsection{Comprobar la recuperacion del servicio}

El servicio se prueba con la misma peticion que antes del incidente. La recuperacion se demuestra con la respuesta, no con el arranque del contenedor.

\begin{lstlisting}[style=estiloCodigo]
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/ \
  | tee semana_09/evidencia/recuperacion.txt
\end{lstlisting}
