\needspace{5\baselineskip}
\section{\iconotexto{user-shield}{Tu rol en la práctica}}

Instrumenta la detección del mismo evento: activa el registro, define la alerta y mide lo que se habría visto, incluidos los falsos positivos y negativos.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Instrumentar el evento, activando el registro que lo vería y definiendo la alerta con su umbral.
  \item Comparar lo que se registró con lo que se ejecutó, ítem por ítem del paso a paso.
  \item Reportar falsos positivos y negativos y proponer el ajuste concreto de la regla.
\end{itemize}

\needspace{5\baselineskip}
\section{\iconotexto{flag}{Qué aporta este rol al entregable}}

La regla o consulta de detección y la tabla de lo detectado frente a lo ejecutado.

\needspace{5\baselineskip}
\section{\iconotexto{list-ol}{Ejemplo paso a paso}}

El rol Púrpura convierte la revision en un control que falla solo. Cada herramienta tiene umbral, veredicto y una salida que se puede citar en el informe.

\subsection{Ejecutar analisis estatico y fijar el umbral}

El umbral se declara antes de mirar el resultado. Un hallazgo de severidad alta bloquea la entrega; los de severidad baja se registran y se deciden.

\begin{lstlisting}[style=estiloCodigo]
mkdir -p semana_07/evidencia
bandit -r semana_07/codigo -f json -o semana_07/evidencia/bandit.json || true
python3 - <<'PY' | tee semana_07/evidencia/bandit_resumen.txt
import json
datos = json.load(open('semana_07/evidencia/bandit.json'))
for hallazgo in datos.get('results', []):
    print(hallazgo['severity'], hallazgo['test_id'], hallazgo['filename'])
PY
\end{lstlisting}

\subsection{Auditar dependencias y generar el inventario}

El inventario de componentes permite saber que se usa y que version. Sin el, una vulnerabilidad publicada no se puede correlacionar con lo instalado.

\begin{lstlisting}[style=estiloCodigo]
pip-audit -r semana_07/requirements.txt \
  -f json -o semana_07/evidencia/pip_audit.json || true
python3 - <<'PY' | tee semana_07/evidencia/sbom.txt
import json
datos = json.load(open('semana_07/evidencia/pip_audit.json'))
for dep in datos.get('dependencies', []):
    print(dep['name'], dep['version'], len(dep.get('vulns', [])))
PY
\end{lstlisting}

\subsection{Buscar secretos antes de que lleguen al historial}

El escaneo mira el arbol y el historial. Un secreto retirado del arbol sigue estando en el commit anterior.

\begin{lstlisting}[style=estiloCodigo]
git grep -nEi '(api[_-]?key|secret|token|password)[[:space:]]*=' \
  > semana_07/evidencia/secretos.txt || true
git log --all -p -S 'BEGIN RSA PRIVATE KEY' --oneline \
  >> semana_07/evidencia/secretos.txt || true
\end{lstlisting}

\subsection{Convertir el resultado en veredicto}

El veredicto por herramienta es pasa, falla o no\_verificado. Si una herramienta no se pudo ejecutar, el veredicto no es pasa.
