\needspace{5\baselineskip}
\section{\iconotexto{user-shield}{Tu rol en la práctica}}

Parte de su propia captura cruda y aplica el control equivalente: configuración, parche o regla de red. Repite el ataque para demostrar que falla y documenta el antes y el después.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Leer su propia evidencia cruda y elegir el control que corta el ataque en el punto más barato.
  \item Aplicar el control y repetir el ataque para demostrar que ya no funciona.
  \item Documentar el antes y el después con los mismos comandos y la diferencia medida.
\end{itemize}

\needspace{5\baselineskip}
\section{\iconotexto{flag}{Qué aporta este rol al entregable}}

La mitigación aplicada, el comando de verificación y la comparación de resultados.

\needspace{5\baselineskip}
\section{\iconotexto{list-ol}{Ejemplo paso a paso}}

El rol Azul escribe la autorizacion pensando en como se comprueba: tasas maximas, herramientas permitidas y un plan de vuelta atras. Una autorizacion sin limites medibles no protege a nadie.

\subsection{Declarar herramientas y tasas permitidas}

La tasa se declara antes de medir y se aplica en el comando. Si el escaneo tarda mas, es correcto: el limite manda sobre la prisa.

\begin{lstlisting}[style=estiloCodigo]
mkdir -p semana_03/evidencia
nmap --version | head -1 > semana_03/evidencia/herramientas.txt
nmap -sT -p 8081,3000,2222 --max-rate 20 127.0.0.1 \
  -oN semana_03/evidencia/roe_scan.txt
grep -E 'Nmap scan report|Not shown|elapsed' \
  semana_03/evidencia/roe_scan.txt
\end{lstlisting}

\subsection{Fijar el plan de vuelta atras}

Antes de tocar configuracion se guarda el estado que permite restaurarla. Si el servicio no arranca despues del cambio, ese archivo es la unica salida.

\begin{lstlisting}[style=estiloCodigo]
docker exec objetivo-web cp /etc/apache2/apache2.conf \
  /tmp/apache2.conf.bak
docker exec objetivo-web sha256sum /tmp/apache2.conf.bak \
  > semana_03/evidencia/rollback.sha256
\end{lstlisting}

\subsection{Definir criterios de parada}

Se declaran tres detenciones: datos personales, indisponibilidad de un servicio y hallazgo que permita acceso fuera del alcance. Cada una tiene quien decide y como se comunica.

\subsection{Verificar que la autorizacion cubre lo que se ejecuta}

Se compara comando por comando con el alcance. Lo que no esta cubierto no se ejecuta, aunque parezca inofensivo.

\section{\iconotexto{box-open}{Qué guardar en el repositorio}}

La autorizacion incluye herramientas, tasas, criterios de parada y plan de vuelta atras, con una verificacion ejecutada para cada limite.

\begin{lstlisting}[style=estiloCodigo]
semana_03/
|-- autorizacion.md
|-- informe.md
|-- evidencia/
|   |-- herramientas.txt
|   |-- roe_scan.txt
|   `-- rollback.sha256

\end{lstlisting}

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item La tasa declarada aparece en el comando y en la salida.
  \item El plan de vuelta atras se probo al menos una vez sin romper el laboratorio.
  \item Los criterios de parada nombran quien decide.
  \item Lo ejecutado no excede lo autorizado, comparado linea por linea.
\end{itemize}
