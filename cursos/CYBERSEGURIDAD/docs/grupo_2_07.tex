\section{\iconotexto{user-shield}{Tu rol en la práctica}}

Verifica que el alcance y la autorización cubran lo ejecutado, anonimiza la evidencia, revisa la cadena de custodia e integra el informe técnico y el resumen ejecutivo.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Revisar que el alcance y la autorización cubran exactamente lo ejecutado, ni más ni menos.
  \item Anonimizar la evidencia y verificar la cadena de custodia de cada archivo entregado.
  \item Integrar informe técnico y resumen ejecutivo, y declarar los límites del trabajo.
\end{itemize}

\needspace{5\baselineskip}
\section{\iconotexto{list-ol}{Ejemplo paso a paso}}

El rol Legal revisa lo que el equipo instala: licencia, origen y riesgo. Una dependencia sin licencia declarada es un problema legal aunque funcione.

\subsection{Inventariar dependencias y licencias}

Se listan las dependencias directas con su version y su licencia. Lo que no se puede verificar se marca como pendiente, no se asume permisivo.

\begin{lstlisting}[style=estiloCodigo]
mkdir -p semana_07/evidencia
python3 -m pip list --format=json > semana_07/evidencia/instalado.json
python3 - <<'PY' | tee semana_07/evidencia/licencias.txt
import json
for paquete in json.load(open('semana_07/evidencia/instalado.json'))[:40]:
    print(paquete['name'], paquete['version'], 'licencia: pendiente de verificar')
PY
\end{lstlisting}

\subsection{Decidir que se acepta en el repositorio}

Se acepta una dependencia si tiene licencia compatible, origen conocido y version fijada. Las que no cumplen se sustituyen o se aisan.

\subsection{Escribir el criterio de aceptacion de seguridad}

El criterio es una condicion verificable: por ejemplo, ninguna consulta se construye por concatenacion y toda ruta de archivo pasa por lista blanca. Se escribe para que otra persona pueda comprobarlo sin preguntar.

\subsection{Comprobar que el criterio se puede auditar}

Cada criterio se asocia a un comando o a una prueba. Si no se puede comprobar de forma automatica, se documenta como revision manual con responsable.

\begin{itemize}[leftmargin=1.4em,itemsep=2pt,topsep=3pt]
  \item Cada dependencia directa tiene licencia o queda como pendiente.

  \item Las versiones estan fijadas en requirements.
\end{itemize}
