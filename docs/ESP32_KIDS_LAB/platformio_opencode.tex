\vspace{6pt}
\begin{tcolorbox}[tarjetaIcono, title={\faIcon{question-circle}~\u00bfPor qu\'e es posible?}]
PlatformIO es, en su n\'ucleo, una \textbf{l\'inea de comandos} (\texttt{pio}). La extensi\'on de VSCode
es solo una interfaz gr\'afica sobre esa misma CLI. Por lo tanto, cualquier terminal ---incluida la de
OpenCode--- puede ejecutar \texttt{pio run}, \texttt{pio device monitor}, subir firmware, gestionar
bibliotecas y configurar \texttt{platformio.ini} con el mismo resultado.
\end{tcolorbox}

% ══ INSTALACIÓN ══════════════════════════════════════════════════════
\section{\iconotexto{download}{Instalaci\'on en este workspace}}

\begin{enumerate}[leftmargin=1.8em, itemsep=4pt]
  \item Instalar el Core en el entorno conda \texttt{elect\_env} (ya hecho):
\begin{lstlisting}
python3 -m pip install platformio
\end{lstlisting}
  \item Verificar que la shell de OpenCode lo resuelve (el plugin \texttt{conda-env.js}
        antepone \texttt{elect\_env}/bin al PATH de cada shell):
\begin{lstlisting}
pio --version
# PlatformIO Core, version 6.2.0
\end{lstlisting}
  \item Opcional: registrar el servidor MCP \texttt{platformio-mcp} en \texttt{opencode.json}
        para que OpenCode exponga herramientas nativas de PlatformIO (board discovery,
        build, flash, monitor, diagn\'ostico):
\begin{lstlisting}[language=json]
"mcp": {
  "platformio": {
    "type": "local",
    "command": ["npx", "-y", "platformio-mcp"],
    "enabled": true,
    "environment": {
      "PATH": "/home/cero/anaconda3/envs/elect_env/bin:/home/cero/.nvm/versions/node/v22.23.1/bin:/usr/bin:/bin"
    }
  }
}
\end{lstlisting}
        Requiere reiniciar OpenCode para que el servidor se cargue.
\end{enumerate}

% ══ FLUJO BÁSICO ════════════════════════════════════════════════════
\section{\iconotexto{project-diagram}{Flujo b\'asico de trabajo}}

\begin{enumerate}[leftmargin=1.8em, itemsep=4pt]
  \item Crear/inicializar un proyecto:
\begin{lstlisting}
pio project init --board esp32-s3-devkitc-1 --project-option "framework=arduino"
\end{lstlisting}
  \item Compilar (equivalente al bot\'on \texttt{Build} de VSCode):
\begin{lstlisting}
pio run
\end{lstlisting}
  \item Subir firmware (equivalente a \texttt{Upload}):
\begin{lstlisting}
pio run --target upload
\end{lstlisting}
  \item Monitor serie integrado:
\begin{lstlisting}
pio device monitor
\end{lstlisting}
  \item Ver puertos disponibles:
\begin{lstlisting}
pio device list
\end{lstlisting}
\end{enumerate}

% ══ PYTHON/SCRIPTS vs CHAT ══════════════════════════════════════════
\section{\iconotexto{cogs}{Regla: comandos deterministas, no decisiones en el chat}}

En ELECTRONICA la l\'ogica repetible vive en scripts deterministas, no improvisada en el chat.
Para flujos PlatformIO reutilizables se sigue la arquitectura de 3 capas: directiva YAML en
\texttt{directives/}, orquestador en la ra\'iz (o servidor MCP), y ejecuci\'on en
\texttt{execution/} con \texttt{pio} vía subprocess. Un comando puntual (compilar, subir)
puede correr directamente desde la shell; un flujo repetible debe quedar documentado como script.

% ══ DIFERENCIAS CON VSCode ══════════════════════════════════════════
\section{\iconotexto{table}{Vista r\'apida: VSCode vs OpenCode}}

\begin{tcolorbox}[tarjetaDato, title={\faIcon{arrows-alt}~Comparativa}]
\begin{tabularx}{\linewidth}{@{}p{4.2cm}XX@{}}
\toprule
\textbf{Operaci\'on} & \textbf{VSCode (extensi\'on)} & \textbf{OpenCode (CLI/MCP)} \\
\midrule
Compilar            & Bot\'on \texttt{Build}            & \texttt{pio run} \quad o herramienta MCP \\
Subir firmware      & Bot\'on \texttt{Upload}           & \texttt{pio run --target upload} \\
Monitor serie       & Panel integrado                   & \texttt{pio device monitor} \\
Libs                & UI gestor de librer\'ias          & \texttt{pio pkg install <lib>} \\
Diagn\'ostico       & PlatformIO Home                   & MCP \texttt{agent\_build\_diagnose} \\
Edici\'on de c\'odigo & Editor + IntelliSense            & OpenCode + tools de edici\'on \\
\bottomrule
\end{tabularx}
\end{tcolorbox}

\begin{tcolorbox}[cajaFortaleza]
\textbf{Limitaci\'on honesta:} VSCode aporta IntelliSense, resaltado de sintaxis y un monitor
serie gr\'afico que OpenCode no replica. Para edici\'on id\'entica, nada impide usar VSCode como
editor y ejecutar \texttt{pio} desde su terminal integrada; con OpenCode ganas que el agente IA
compile, suba y diagnostique por ti sin cambiar de herramienta.
\end{tcolorbox}
